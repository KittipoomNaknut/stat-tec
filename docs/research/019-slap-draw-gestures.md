# 019 — ท่าตบ (slap) และท่าวาด (draw) จาก cursor

- **วันที่:** 2026-10-29 · **สถานะ:** สรุปแล้ว (รอลองสด)
- **เกี่ยวข้อง:** `app/src/gestures/slap.ts` · `draw.ts` · `engine.ts` · `input/mouse-adapter.ts` · `config/gestures.ts` (`slap`) · `tests/replay/slap-draw.test.ts`

## คำถาม

EPISODE IV (จับโกง) ต้องการท่า **ตบ** ส่วน EPISODE V (พยากรณ์) ต้องการท่า **วาดเส้น** แต่ระบบมีแค่ cursor / dwell / raise จะสร้างสองท่านี้ยังไงให้แม่นและนิ่งเท่ากับ cursor ที่จูนมาแล้ว (research 009–015)

## แนวคิด

ทั้งสองท่าอ่านจาก **cursor ที่กรองแล้ว** แทนการอ่านข้อมือตรง ๆ

- ตำแหน่งที่ตบหรือวาดโดน = ตำแหน่งที่ผู้เล่นเห็นมือตัวเองบนจอพอดี
- ได้ตัวกรองที่จูนไว้แล้วมาฟรี ทั้ง activation, straightness, side zone และ smoothing
- เมาส์ (F2) กับร่างกายทำงานเหมือนกัน E2E จึงทดสอบได้โดยไม่ต้องใช้กล้อง

## ข้อมูลที่ใช้

คลิปที่อัดไว้แล้ว ไม่ได้เปิดกล้อง: `2026-10-28-adult1-2m-rtmpose` (มีคลิป slap / swipe / draw / point / idle), `2m-indoor` (MediaPipe) และ playground 2 ชุด ทุกคลิป replay ผ่านโซ่เดียวกับ engine (PoseTracker → CursorTracker → CursorSmoother → detector) หน่วยความเร็ว = **ความสูงจอต่อวินาที** (แกน x คูณ 16/9)

## การทดลอง

### รอบที่ 1 — ความเร็วรายเฟรม

| คลิป                   | p95      | p99   | max   |
| ---------------------- | -------- | ----- | ----- |
| playground (side zone) | 1.54     | 2.48  | 4.39  |
| point-hold             | **4.26** | 5.24  | 5.91  |
| swipe                  | 4.82     | 6.61  | 7.13  |
| slap                   | 9.93     | 14.30 | 15.45 |

ตอนชี้ค้างนิ่ง ๆ (point-hold) p95 ขึ้นถึง 4.26 ทั้งที่มือไม่ได้ขยับเร็ว แปลว่าค่ารายเฟรมมีสัญญาณรบกวนกระโดดเป็นช่วง ๆ ถ้าใช้เป็นเกณฑ์จะตบเองตอนชี้ปุ่ม → ไม่ใช้

### รอบที่ 2 — ความเร็วเฉลี่ยในหน้าต่าง 100 ms (นับเฟรมที่เร็วกว่า 3)

| คลิป                        | เฟรม > 3 | p99  |
| --------------------------- | -------- | ---- |
| playground side zone (56 s) | 4        | 2.39 |
| playground กรอบเก่า (90 s)  | 34       | 3.73 |
| swipe (7 s)                 | 35       | 5.93 |
| free-play (29 s)            | 52       | 5.35 |

ตอนชี้ปุ่มด้วยกรอบปัจจุบัน p99 = 2.4 ส่วนท่าปัดตั้งใจขึ้นไป 4–7 → ตั้งเกณฑ์ **เริ่ม 3.5 / คงไว้ 2.5** (hysteresis ช่วงท้ายของการปัดที่ช้าลงจะยังไม่หลุด) และทิ้ง 60 ms แรกหลัง cursor โผล่ เพราะช่วงสั้นเกินจะวัดความเร็วได้

### รอบที่ 3 — นับเป็นครั้ง (ช่วงที่ active ติดกัน) บน cursor ที่กรองแล้ว

| คลิป (RTMPose)                 | ตบ    | เส้นที่วาด |
| ------------------------------ | ----- | ---------- |
| swipe: ปัด 6 ครั้ง             | **5** | 2          |
| slap: ตบไปข้างหน้า 8 ครั้ง     | 2     | 5          |
| draw                           | 0     | **1**      |
| walk / idle / fidget           | 0     | 0          |
| point-right-sweep, raise-right | 0     | —          |
| raise-both                     | 3     | 2          |
| playground side zone (56 s)    | 2     | 3          |

- **ปัดข้ามจอ** จับได้ 5/6 ถือว่าพอสำหรับเกม เพราะตอนเล่นปัดได้เรื่อย ๆ
- **ตบไปข้างหน้า** (เข้าหากล้อง) ได้แค่ 2/8 เพราะแขนหดในภาพ 2D แบบเดียวกับปัญหาปุ่ม 5 ใน research 010 → ในเกม **สอนให้ปัดข้าง** ไม่ใช่ตบเข้าหาจอ
- ยกสองแขน (raise-both) ยังดูเหมือนชี้ (ปัญหาเดิมที่รู้อยู่แล้ว) แต่ EPISODE IV ฟัง slap แค่ตอนเล่น จึงไม่กระทบบทอื่น
- MediaPipe (2m-indoor): swipe 3/6 และเส้นวาดขาดเป็น 6 ท่อน เพราะ cursor หลุดบ่อยกว่า → เป็นแค่ตัวสำรอง ยอมรับได้

## ท่าวาด

ปากกาลงเมื่อ cursor โผล่ ยกปากกาเมื่อ cursor หาย หรือเมื่อเปลี่ยนมือ ไม่ต้องมีกฎใหม่ เพราะ cursor กรองการขยับมั่วไว้แล้ว ผลคือคลิป draw ได้ 1 เส้นไม่ขาด และตอนยืนเฉยไม่มีเส้นเลย

ฉากพยากรณ์จะใช้เส้นแบบ "แปรงทา" คือแต่ละเดือนรับค่า y ล่าสุดที่ cursor ผ่าน จุดที่ปากกาลงผิดที่ตอนยกแขนจึงถูกทาทับได้

## ทางเลือกที่ไม่เลือก

- **อ่านความเร็วข้อมือใน body space:** ได้ท่าตบไปข้างหน้าด้วย แต่ตำแหน่งที่โดนจะไม่ตรงกับ cursor ที่ผู้เล่นเห็น และเมาส์ทดสอบแทนไม่ได้
- **ท่าวาดที่ต้องกำมือ / ยกมือเหนือไหล่:** ยังไม่มี hand landmarks (ROADMAP 6.8) และเพิ่มกฎที่น้องต้องจำ

## ข้อสรุป

`SlapDetector` (หน้าต่าง 100 ms, 3.5 / 2.5 ความสูงจอ/วินาที) กับ `DrawDetector` (ปากกา = cursor โผล่) ใส่ใน GestureEngine แล้ว เมาส์สะบัดเร็วก็ตบได้ด้วย มี replay test ล็อกตัวเลขในตารางรอบที่ 3 ไว้

## ข้อจำกัด / ต้องทดสอบต่อ

- ข้อมูลมาจากผู้ใหญ่คนเดียว เด็กอาจปัดช้ากว่านี้ ต้องลองสดแล้วอาจลดเกณฑ์
- ความเร็ววัดเป็นความสูงจอ ถ้าจอหน้างานไม่ใช่ 16:9 ต้องแก้ `aspect`
