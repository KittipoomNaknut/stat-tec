# 014 — E2E ด้วยผู้เล่นสังเคราะห์: ทดสอบทั้งรอบโดยไม่ใช้กล้อง

- **วันที่:** 2026-10-29 · **สถานะ:** สรุปแล้ว
- **เกี่ยวข้อง:** `app/src/debug/synthetic-player.ts` · `app/tests/e2e/visit.spec.ts` · `.github/workflows/ci.yml` (job `e2e`) · PR #41

## คำถาม

DoD ของ Phase 3 คือ "เล่นได้ครบรอบด้วยร่างกาย" และ "E2E ผ่านใน CI" — CI ไม่มีกล้อง และวิดีโอปลอม (`.y4m` ตามแผนเดิมใน ARCHITECTURE §15) ต้องมีคนจริงในวิดีโอที่ชี้ปุ่มตรงตำแหน่งพอดี ซึ่งเปลี่ยนทุกครั้งที่ layout เปลี่ยน

## ทางที่เลือก: ร่างกายสังเคราะห์ใน body space

`?player=synthetic` แทนกล้องด้วยร่างกายที่เขียนสคริปต์ได้ → ส่งเข้า **GestureEngine ตัวจริง** (presence, เกณฑ์เริ่มชี้ แขนตรง/สูง/เหยียด, พื้นที่มือข้างตัว, dwell 1.2 s)

- ชี้แบบคน: ยกแขนออกข้าง (ผ่านเกณฑ์เริ่ม) → เลื่อนข้อมือไปตำแหน่งในพื้นที่มือข้างตัวที่ตรงกับปุ่ม (คำนวณย้อนจาก `config/gestures.ts`)
- Playwright หา "จุดกลางปุ่ม" จาก DOM จริง → ไม่ผูกกับ layout
- ส่วนที่ไม่ได้ทดสอบ: กล้อง + โมเดล pose (มี replay test จาก session จริงอยู่แล้ว)

## การทดลอง

### รอบที่ 1 — `?speed=4`: 2 ใน 4 test ล้ม

ไล่ดูทีละ 200 ms: cursor ยังเลื่อนไม่ถึงปุ่ม tutorial ก็จบแล้ว

- tutorial รอ 8 s **เวลาเรื่อง** = 2 s จริงที่ ×4 แต่ dwell ใช้ **เวลาจริง** 1.2 s + เวลาเลื่อนมือ
- Chromium headless ของ Playwright เรนเดอร์ WebGL ด้วย CPU: **8.6 fps** ที่ 1080p

### รอบที่ 2 — เจอปัญหาจริงของผู้เล่นด้วย

ถ้าเวลาหมดตอนผู้เล่น**กำลังค้างอยู่บนปุ่ม** ปุ่มจะหายไปใต้มือ — เกิดกับคนจริงได้ (tutorial 8 s, play) → `NarrativeEngine.setEngaged()`: ระหว่าง dwell บนปุ่มของฉาก (ไม่นับปุ่มข้าม) tutorial/play รอจนเลือกเสร็จหรือเลื่อนออก + unit test

### รอบที่ 3 — ×3 + `maxh=360` + มือเร็วขึ้น (ยก 150 ms, เลื่อน 300 ms)

headless 8.6 → **49.8 fps**; dwell ขึ้นจริง (0.07 → 0.6 ใน 0.6 s)

### รอบที่ 4 — test บอกว่าเลือกเสร็จใน 230 ms ซ้ำ ๆ (เป็นไปไม่ได้: dwell 1.2 s)

**บั๊กจริง:** ปุ่มตัวเลือกของ play และของ reveal ในบท segments ใช้ id เดียวกัน (`d-segmentation-choice-0`) → test อ่านค่าเก่า และ**สำหรับผู้เล่นจริง cooldown 800 ms ของปุ่มแรกจะติดไปที่ปุ่มชุดใหม่** → id รวมชื่อชุด (`…-play-0`, `…-choose-segment-0`)

### รอบที่ 5 — ใน CI: ชี้ปุ่ม ฿45 แต่ได้ ฿75 (ทั้ง 2 ครั้งที่ลอง)

**บั๊กจริง:** หลังกด "พร้อมแล้ว" (กลางจอ) มือยังยกค้างอยู่ตรงกลาง → พอบทกาแฟโชว์ปุ่มราคา ปุ่ม ฿75 **โผล่มาใต้ cursor พอดี** แล้วถูกเลือกเองใน 1.2 s ก่อนมือจะเลื่อนไป ฿45 (เครื่อง local เร็วกว่าเลยรอดโดยบังเอิญ) — คนจริงที่ยกแขนค้างก็โดนแบบเดียวกัน
**แก้:** `DwellDetector` — ปุ่มที่**ปรากฏขึ้นใต้ cursor** ยังเลือกไม่ได้จนกว่า cursor จะออกจากปุ่มก่อนหนึ่งครั้ง (ต้องตั้งใจชี้เข้ามา) + unit test; test เดิมของ dwell/dwell-log ต้องระบุว่าปุ่มอยู่บนจอก่อน (priming) — พฤติกรรมเดิมไม่เปลี่ยนสำหรับปุ่มที่อยู่ก่อนแล้ว; replay test ของ playground ผ่านเหมือนเดิม

## ข้อสรุป

- E2E = ร่างกายสังเคราะห์ผ่าน gesture engine จริง (ไม่ใช่ `.y4m`) — ทดสอบสิ่งที่ผู้เล่นทำจริง (ยกแขน ชี้ ค้าง) และทน layout เปลี่ยน
- time-out ของเรื่องต้องไม่ตัดการเลือกที่กำลังทำ
- id ของเป้าต้องไม่ซ้ำข้ามชุด
- ปุ่มที่โผล่ใต้มือ ต้องให้ผู้เล่นชี้เข้ามาใหม่ก่อน

## ข้อจำกัด

- ไม่ครอบคลุมกล้อง/โมเดล — ครอบคลุมด้วย replay test (`tests/replay`) และ playtest
- ร่างกายสังเคราะห์นิ่งสมบูรณ์ ไม่มี jitter — dwell จริงยังต้องดูจาก playtest (research 010)
