# 026 — เปิดบูธด้วยคำสั่งเดียว และ log สดที่เห็นปัญหาทันที

- **วันที่:** 2026-11-03 · **สถานะ:** สรุปแล้ว (ทดสอบด้วยกล้องที่ไม่มีอยู่จริง + เบราว์เซอร์ headless · ยังไม่ได้ลองกับกล้องจริง)
- **เกี่ยวข้อง:** `scripts/demo.sh` · `perception-server/.../monitor.py` · `server.py` · `viewer.py` (`stat-tec-log`) · `app/src/core/booth-log.ts` · `perception/{protocol,client,perception.worker}.ts` · `experience/experience.ts` · `hud/pose-prompt.ts`

## โจทย์ (เจ้าของงาน)

- เปิด/ปิดเดโมให้ง่าย ไม่ลืมปิดจนเครื่องร้อน
- "ทำ log แบบ real time ได้มั้ย" → "เอาให้เห็นเวลาเกิดปัญหา"

## สิ่งที่ทำ

- **`./scripts/demo.sh start`:** build เกมเฉพาะเมื่อโค้ดเปลี่ยน → เปิดตัวจับท่า → เสิร์ฟเกมที่ `127.0.0.1:8080` (`vite preview`) → เปิด Chrome kiosk ด้วยโปรไฟล์แยก
  - **ปิด Chrome แล้วทุกอย่างปิดตาม**
  - `stop` ปิดเฉพาะ process group ที่สคริปต์เปิด (จำ pid ไว้) · `status` · `log`
  - `--no-kiosk` เปิดแค่ service · `STAT_TEC_PERCEPTION_ARGS` ส่ง flag ให้ตัวจับท่า · `STAT_TEC_CACHE` ย้ายที่เก็บ log
- **เกมส่งเหตุการณ์** ผ่าน WebSocket เส้นเดิมไปที่ตัวจับท่า ถ้ายังต่อไม่ได้ จะเก็บคิวไว้ก่อน
  - เหตุการณ์: เริ่ม/จบรอบ, บท, ท่าที่เลือกหรือหมดเวลา (พร้อมเวลาที่ใช้), เดินออกกลางคัน, error, watchdog, ตัวจับท่าเงียบ, F5
  - fps ของเกมทุก 5 วิ
- **ตัวจับท่าตรวจปัญหาเอง ทุก 1 วิ:** ปัญหาต้องเป็นอยู่นานพอถึงจะ "เปิด" และต้องดีอยู่นานพอถึงจะ "หาย" (กันกระพริบ) แต่ละครั้งเขียน log แค่ 2 บรรทัด คือตอนเริ่มกับตอนหาย (บอกว่าเป็นอยู่นานเท่าไร)

| ปัญหา       | เปิดเมื่อ                                  | หายเมื่อ             |
| ----------- | ------------------------------------------ | -------------------- |
| camera-lost | ไม่มีเฟรม ≥ 2 วิ (ก่อนเฟรมแรกให้เวลา 5 วิ) | มีเฟรมใน 0.5 วิ 1 วิ |
| low-fps     | กล้อง < 20 fps นาน 3 วิ                    | ≥ 24 fps นาน 3 วิ    |
| slow-pose   | จับท่า > 40 ms นาน 5 วิ                    | < 30 ms นาน 3 วิ     |
| app-missing | ไม่มีหน้าเกมต่ออยู่ 15 วิ                  | ต่อกลับมา            |
| app-slow    | เกม < 30 fps นาน 10 วิ                     | ≥ 45 fps นาน 5 วิ    |
| gpu-hot     | GPU ≥ 85°C นาน 10 วิ                       | < 80°C นาน 10 วิ     |
| cpu-hot     | CPU ≥ 95°C นาน 10 วิ                       | < 88°C นาน 10 วิ     |
| on-battery  | ถอดสายชาร์จ 2 วิ                           | เสียบกลับ            |

- **`./scripts/demo.sh log`** (หน้าจอ terminal วาดใหม่ทุก 1 วิ):
  - บรรทัดสุขภาพเครื่อง ระบายสีเขียว/เหลือง/แดง
  - **กล่องแดง "ปัญหาที่ยังไม่หาย"** บอกว่าเป็นตั้งแต่กี่โมง นานเท่าไร และ **ต้องทำอะไร** · ตีกระดิ่ง terminal ตอนมีปัญหาใหม่
  - ตัวเลขวันนี้: จำนวนรอบ, จบ/ออกกลางคัน, เวลาเฉลี่ย, ท่าหมดเวลา, จำนวนปัญหา, error
  - เหตุการณ์ล่าสุดเป็นภาษาไทย
  - ถ้าตัวจับท่าไม่ทำงาน (status.json เก่ากว่า 5 วิ) จะขึ้นแดงเป็นบรรทัดแรก
- **ไฟล์:** `~/.cache/stat-tec/logs/events-YYYY-MM-DD.jsonl` (หนึ่งเหตุการณ์ต่อบรรทัด + health ทุก 60 วิ) และ `status.json`
  - เก็บแค่ชื่อเหตุการณ์กับตัวเลข ไม่มีภาพหรือพิกัดร่างกาย (ARCHITECTURE §17)
  - เหตุการณ์จากเกมถูกกรองก่อนเขียน: ชื่อยาวไม่เกิน 40 ตัว, ค่าแบนไม่เกิน 12 ช่อง, ข้อความไม่เกิน 300 ตัว

## ผลทดสอบ

- **กล้องที่ไม่มีอยู่จริง (`--camera 99`):** เกม build และเสิร์ฟได้ (HTTP 200) · กล่องแดง "กล้องไม่ส่งภาพ" ขึ้นหลังเริ่ม 5 วิ พร้อมคำแนะนำ · `stop` ปิดหมด ไม่เหลือ port ค้าง
- **เบราว์เซอร์ headless เปิดเกมที่ build แล้ว:** log เห็น "หน้าเกมเชื่อมต่อแล้ว", F5 และ "หลุดการเชื่อมต่อ" · `status.json` ได้ fps ของเกม = 59
- **E2E ทั้งรอบ:** ลำดับเหตุการณ์ = visit-start → ท่า 🙌 → 3 บท (บทละ chapter → pose → chapter-done) → visit-end
- **unit:** debounce ของปัญหา (รวมกรณีเริ่มที่เวลา 0 ซึ่งเจอบั๊ก `or` กับ 0 แล้วแก้), การกรองเหตุการณ์, การอ่านไฟล์ทีละบรรทัดเต็ม, หน้าจอ log

## เจอระหว่างทาง

- `XDG_CACHE_HOME` ย้าย cache ของ corepack ไปด้วย ทำให้โหลด pnpm ผิดเวอร์ชันแล้ว build พัง → สคริปต์ใช้ `STAT_TEC_CACHE` ของตัวเอง และเรียก pnpm จากใน `app/`
- เทสต์ฝั่ง service: client ที่หยุดอ่านข้อความทำให้การปิด WebSocket ค้าง 10 วิ → ให้เทสต์อ่านต่อจนจบ
