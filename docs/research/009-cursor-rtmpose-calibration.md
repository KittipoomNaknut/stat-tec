## คำถาม / สมมติฐาน
เปลี่ยนเป็น RTMPose แล้วเกณฑ์ cursor จาก [004](004-cursor-rules-v1.md) ยังใช้ได้ไหม
replay ทุก test กับ session ใหม่: **ล้ม 9 จาก 156**

## การทดลอง
### รอบที่ 0 — แยกกลุ่มและหาสาเหตุทีละเคส
**กลุ่ม A (ล็อก):** ไม่ใช่บั๊ก — ตอนคลิปเริ่มเจ้าของงานยังเดินกลับเข้ากลางจอ (torso x 0.01 → 0.31), และเดินกลับเข้ามาก่อนคลิป walk-in-out จบ (→ ผู้เล่น #2 ถูกตามออกแบบ) → แก้ test ให้วัดสิ่งที่สำคัญ (ล็อกภายใน 0.7 s นับจากเป็น candidate, "คนอื่น" เฉพาะตอนมีผู้เล่น)

**กลุ่ม B (cursor):**
| | MediaPipe | RTMPose |
|---|---|---|
| เกาหัว/กอดอก: extension | 0.26–0.60 | **0.34–1.12** |
| cursor โผล่ตอน fidget | 0% | **22% + ปุ่มเต็มจอถูกกด 1 ครั้ง** |
สาเหตุ: **กอดอก** — ข้อมืออยู่อีกฝั่งของลำตัว ห่างไหล่ 1.1 SW ดูเหมือน "เหยียด"

### รอบที่ 1 — สมมติฐาน "แขนตรง" = ไหล่–ข้อมือ ÷ (ต้นแขน + ปลายแขน)
| | 5–95% |
|---|---|
| fidget | 0.19–0.40 (MP) · 0.23–0.76 (RTM) |
| ชี้ | 0.46–1.00 (MP) · 0.56–1.00 (RTM) |
ข้อดี: ชี้เข้ากล้องแขนสั้นลงทั้งท่อนแต่ยังเป็นเส้นตรง → ค่าไม่เปลี่ยน

### รอบที่ 2 — grid เกณฑ์เริ่ม (แขนตรง)
| act | MP fidget | MP left-sweep span | RTM fidget |
|---|---|---|---|
| 0.8 | 0 | **0.52** | **0 / 0 select** |
| 0.75 | 0 | – | 44 frames / **1 select** |
| 0.7 | 0 | **1.00** | 45 / **1 select** |
→ สองโมเดลต้องการค่าต่างกัน

### รอบที่ 3 — cursor ตอนชี้ RTMPose ได้แค่ ~77% ทุกค่า → ไม่ใช่เพราะกฎแขนตรง
ไล่ทีละเฟรม:
- right sweep: `hand-low` 20 เฟรม (ลดมือถึงระดับสะโพก) + รอเริ่มใหม่ 24 เฟรม
- left sweep: `ext < 0.6` ต่อเนื่อง 1.27 s → ตอนนั้น ext 0.28–0.53 แต่ **แขนตรง 0.68–0.83**, มือสูง 1.8–2.1 = ชี้เข้ากล้อง
→ เพิ่มกฎค้าง: แขนดูสั้นได้ถ้ายังตรง ≥ 0.65 → left sweep 0.78 → **0.95**

### รอบที่ 4 — ลดเกณฑ์ปล่อยความสูงไหม
| release | 0.3 | 0.2 | 0.1 | 0.0 |
|---|---|---|---|---|
| RTM right sweep | 0.77 | 0.78 | 0.79 | 1.00 |
**ไม่ลด:** idle-stand ข้อมือที่ห้อยอยู่ต่ำกว่าสะโพกแค่ 0.03–0.06 SW → ที่ 0.0 cursor อาจค้างตอนปล่อยแขน

### รอบที่ 5 — point-hold ยังกดไม่ได้
test วางปุ่มที่ "กลางของเฟรมที่ cursor แสดง" ซึ่งตกช่วงมือซ้ายที่กำลังเคลื่อน; จุดค้างจริงคือมือขวานิ่ง 2.33 s → test วางปุ่มที่จุดนิ่งที่สุด (และตรวจว่ามีช่วงนิ่ง ≥ 1.2 s จริง) → ผ่าน

## ข้อสรุป
- กฎแขนตรง: เริ่ม ≥ 0.8 (RTMPose) / 0.7 (MediaPipe), ค้าง ≥ 0.5, แขนดูสั้นแต่ตรง ≥ 0.65 ยังค้างได้
- เกณฑ์แยกตามแหล่ง pose; GestureEngine เลือกตามแหล่งที่ใช้จริง
- 158 test ผ่านบนทั้งสอง session

## ทางเลือกที่ไม่เลือก
- ใช้ score ของ RTMPose กรองข้อมือที่ซ่อน — ข้อมือที่ซ่อนได้ 0.45–0.85 แยกไม่ออก
- เกณฑ์เดียวสำหรับทั้งสองโมเดล — grid แสดงว่าไม่มีค่าเดียวที่ผ่านทั้งคู่

## ข้อจำกัด / ต้องทดสอบต่อ
- **ชูสองแขน = ดูเหมือนชี้** (ตรง สูง) → กดปุ่มได้ทั้งสองโมเดล; ฉากที่มีทั้งปุ่มและท่าชูแขนต้องปิด cursor ช่วงนั้น
- ยังไม่ได้ลองสดกับกฎใหม่ → [010](010-dwell-failures.md)
