# 001 — Benchmark MediaPipe lite / full / heavy

- **วันที่:** 2026-10-28 · **สถานะ:** สรุปแล้ว (โมเดลหลักถูกแทนด้วย RTMPose ใน [006](006-pose-model-spike.md); heavy ยังเป็นโมเดลของ fallback)
- **เกี่ยวข้อง:** PR #9, #10, #11 · [ADR-0005](../adr/0005-pose-model-heavy.md) · [benchmarks/phase1.md](../benchmarks/phase1.md) · ข้อมูลดิบ `docs/benchmarks/data/2026-10-28-builtin-webcam-720p30.json`

## คำถาม / สมมติฐาน
เจ้าของงานบอกว่า skeleton "สั่นสุด ๆ" และถามว่าใช้โมเดลที่หนักกว่าได้ไหม
สมมติฐาน: โมเดลใหญ่แม่นกว่า แต่อาจช้าเกินงบ 33 ms/เฟรม (กล้อง 30 fps)

## ข้อมูลที่ใช้
Chrome 156, RTX 4060 Laptop, เว็บแคมในตัว 720p30, เจ้าของงานยืนนิ่ง ~2 m, `/?bench` รุ่นละ 15 s (457 เฟรม)

## การทดลอง
### รอบที่ 1 — smoke run (5 s/รุ่น, นั่งใกล้กล้อง, มีอีกแท็บรันอยู่)
lite 14.1 / full 15.2 / heavy 17.3 ms — lite ≈ heavy ซึ่งผิดปกติ
→ **ไม่เชื่อผล**: อีกแท็บใช้ GPU แย่งกัน ต้องวัดแท็บเดียว

### รอบที่ 2 — ยืน 2 m, แท็บเดียว
| Model | Inference avg / p95 | FPS | Jitter raw → filtered |
|---|---|---|---|
| lite | 14.9 / 22.2 ms | 30.5 | 5.78 → 0.77 px |
| full | 15.6 / 20.8 ms | 30.5 | 5.34 → 0.71 px |
| heavy | 16.9 / **18.8** ms | 30.5 | **4.56 → 0.58** px |

**ข้อสังเกต:** โมเดลใหญ่กว่า 5 เท่าแต่ช้ากว่าแค่ ~2 ms → เวลาส่วนใหญ่ (~14 ms) เป็นค่าใช้จ่ายคงที่ของ pipeline ไม่ใช่ขนาดโมเดล

### ระหว่างทาง: กราฟใน benchmark ป้ายทับกัน (PR #10)
ขีด p95 ทับตัวเลข, ป้าย "camera" ทับ "30.5 fps" → ย้ายป้ายอ้างอิงไปแถบบน, ตัวเลขระบุ `avg · p95` ชัด, ใส่ halo — ตรวจซ้ำด้วยภาพหน้าจอจริงทั้ง 3 กราฟ

## ข้อสรุป
ใช้ heavy: นิ่งสุด, p95 ต่ำสุด, แลกแค่ ~2 ms

## ข้อจำกัด / ต้องทดสอบต่อ
- เว็บแคมในตัว 720p30 — ถ้าใช้กล้อง 60 fps งบเหลือ 16.7 ms ซึ่ง p95 ของ heavy (18.8 ms) เกิน
- ยังไม่ได้วัด motion-to-photon latency (เลื่อนไปวัดกับกล้องจริง)
