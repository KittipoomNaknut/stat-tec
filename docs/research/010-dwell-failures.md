# 010 — ทำไมปุ่มบางครั้งไม่ติด

- **วันที่:** 2026-10-28 – 29 · **สถานะ:** สรุปแล้ว (หลุดเป้าที่เหลือเปิดไว้เป็นงานต่อ)
- **เกี่ยวข้อง:** ต่อจาก [009](009-cursor-rtmpose-calibration.md)

## คำถาม / สมมติฐาน
เจ้าของงานลอง `?playground` กับ RTMPose: "โอเค แต่บางครั้งปุ่มไม่ติด"
สาเหตุที่เป็นไปได้ (ยังไม่รู้ว่าข้อไหน):
1. cursor **ขยับหลุดปุ่ม**ระหว่างค้าง 1.2 s (เกิน grace 150 ms)
2. cursor **หายชั่วขณะ** (กฎแขนตรง / ความสูง / visibility ตัด)
3. เจ้าของงาน**รอไม่ถึง 1.2 s** แล้วเปลี่ยนใจ

## วิธีวัด
- playground บันทึกทุก "ความพยายามกด" (dwell เริ่ม → สำเร็จ / ไม่สำเร็จพร้อมสาเหตุและ progress ที่ไปถึง) + อัดท่า raw ไปพร้อมกัน
- เล่น 1–2 นาที → วิเคราะห์อัตราสำเร็จและสาเหตุ → ปรับ → **replay ท่าเดิม**พิสูจน์ว่าดีขึ้น

## เครื่องมือ (PR นี้)
- `debug/dwell-log.ts` — ทุก dwell ที่เริ่มขึ้น จบเป็น: **selected** / **left-target** (cursor ยังแสดงแต่ออกนอกปุ่ม + ระยะที่ออกไป) / **cursor-hidden** (cursor หายตอนหลุด) / **passed-by** (ไปไม่ถึง 25% — แค่เลื่อนผ่าน ไม่นับเป็นความล้มเหลว; 25% เป็นค่าที่ตั้งเอง ข้อมูลอาจบอกให้ปรับ)
- playground แสดงสรุปสด และ **F9** ดาวน์โหลด `*.attempts.json` (ปุ่ม, viewport, ผลทุกครั้ง) + `*.pose.json.gz` (ท่าทั้ง session) สำหรับ replay
- ทดสอบ: unit test ป้อน cursor ผ่าน `DwellDetector` ตัวจริง 5 กรณี; F9 ทดสอบใน Chrome ด้วยกล้องสังเคราะห์ (กล้องจริงไม่ถูกเปิด) — ได้ 2 ไฟล์ครบ

## การทดลอง

### รอบที่ 1 — เจ้าของงานเล่น playground กับ RTMPose (2026-10-28, ~1.5 นาที, เว็บแคมในตัว + จอโน้ตบุ๊ก)
ไฟล์: `app/tests/fixtures/poses/2026-10-28-adult1-playground-rtmpose.pose.json.gz` (2757 เฟรม) + `app/tests/fixtures/playground/2026-10-28-adult1-rtmpose.attempts.json`

| | ผล |
|---|---|
| ปุ่ม 1, 2, 3, 4, 6 | กดติด **22/24 (92%)** — พลาด: ปุ่ม 3 หลุดขอบ 0.002, ปุ่ม 4 cursor หาย |
| **ปุ่ม 5 (ล่างกลาง = หน้าตัว)** | **0** — มีครั้งเดียวที่ cursor แตะ (0.16 s, 3%) แล้วหาย |
เจ้าของงาน: "กด 5 ที่อยู่ข้างหน้าตัวไม่ค่อยได้" — ตรงกับข้อมูล

### รอบที่ 2 — ทำไมปุ่ม 5 (replay ท่าที่อัด)
ทุกเฟรมที่มือที่ยกอยู่ "จะ" พา cursor ไปปุ่ม 5: ซ่อนเพราะ `ext < 0.25` 25 ครั้ง, `สั้นและงอ` 29 ครั้ง, เริ่มไม่ได้ 6 ครั้ง, แสดงจริงแค่ 2
ข้อมือขวาอยู่ (0.05…0.56, −0.2) = **ทับไหล่ขวา** → ext 0.13–0.59, "แขนตรง" **0.16–0.60**
→ **สมมติฐานใน [009](009-cursor-rtmpose-calibration.md) ผิดบางส่วน**: ชี้เข้ากล้องแบบเอียงแขนยังตรงในภาพ แต่ชี้ **ตรง** เข้ากล้อง ท่อนแขนสั้นจนตำแหน่งศอกที่คลาดนิดเดียวทำให้ค่า "แขนตรง" พัง

### รอบที่ 3 — แยก "ชี้เข้ากล้อง" กับ "มือหน้าอก" ด้วยความยาวต้นแขนในภาพ
| | ต้นแขน (5% · กลาง · 95%) |
|---|---|
| เล็งปุ่ม 5 | 0.27 · 0.35 · 0.64 |
| fidget RTMPose | 0.39 · 0.61 · 0.79 |
**ซ้อนกันมาก → ใช้ไม่ได้** · สรุป: จากภาพ 2 มิติกล้องเดียว สองท่านี้แยกกันแทบไม่ได้

### รอบที่ 4 — สร้างตัววัด: replay playground กับปุ่มตำแหน่งเดิม
replay ได้ **22 ครั้ง กระจายรายปุ่มตรงกับตอนเล่นจริงทุกปุ่ม** (ปุ่ม 5 = 0) → ใช้เป็นตัววัดทางแก้ได้

### รอบที่ 5 — "ยกมือค้างไว้ = ชี้ต่อ" (`keepWhileAboveHips`, เกณฑ์เริ่มเหมือนเดิม)
| ค่า | กดติด | ปุ่ม 5 | fidget MP / RTM | ยืนนิ่ง | ชูสองแขน |
|---|---|---|---|---|---|
| ปิด | 22 | 0 | 0 / 0 | 0 | 2 sel (เหมือนเดิม) |
| 1.2 | 23 | 0 | 0 / 0 | 0 | 2 |
| 1.0 | **24** | 0 | 0 / 0 | 0 | 2 |
| 0.8 | 24 | 0 | 0 / 0 | 0 | 2 |
กู้ 2 ครั้งที่พลาดได้ โดยไม่เพิ่มการโผล่ตอน fidget — **แต่ปุ่ม 5 ยัง 0**

**ต้นเหตุจริง:** ระบบแปลง*ตำแหน่ง*ข้อมือเป็น cursor แต่คน*ชี้ด้วยทิศทาง* — ปุ่มขอบจอ ทิศกับตำแหน่งไปด้วยกัน; ปุ่มหน้าตัว แขนชี้เข้ากล้อง ข้อมือตกที่ไหล่ → cursor ไปอยู่ขอบปุ่ม 5 และกระโดดข้ามขอบ

**ข้อจำกัดของการทดลอง:** จอโน้ตบุ๊กเล็ก กล้องอยู่ขอบบน — จาก 2 m ทุกจุดบนจอแทบอยู่ทิศเดียวกับกล้อง; บนทีวีใหญ่ปัญหาน่าจะเบาลงแต่ไม่หาย (ยังไม่ได้วัด)

### รอบที่ 6 — เปลี่ยนวิธีคุม: "พื้นที่มือข้างตัว" (เจ้าของงานเลือกตามที่แนะนำ)
ทางเลือกที่เสนอ: (ก) พื้นที่มือข้างตัวแบบ Kinect, (ข) กฎไม่วางปุ่มหน้าตัว, (ค) ทั้งคู่ → เลือก ก + keep ที่ 1.0 + เขียน ข เป็นแนวทางสำรอง

ออกแบบจากข้อมูลแขนเหยียดตรงที่ยกขึ้น (ทุก session): ยื่นออกด้านข้าง 1.4–1.5 SW (สูงสุด 1.9–2.1), ความยาวแขน ~1.5 SW (98%: 2.0)
- กรอบเดิม x −1.4…1.7, y −1.3…0.5 → **ใหม่ x 0.4…1.7 (ออกด้านข้าง), y −1.2…0.3** (มือซ้ายสะท้อน)
- กลางจอ = ข้อมืออยู่นอกไหล่ ~0.55 SW (ไม่ยุบเข้ากล้อง); ข้อมือบนไหล่ตัวเองไปตกนอกกลางจอ (unit test คุม)
- มุมบน-นอก ห่างไหล่ 1.7 SW ≈ ความยาวแขน (ต้องเอื้อม)
- ข้อแลก: กรอบแคบลง 3.1 → 1.3 SW → cursor ไวขึ้น ~2.4× (ประมาณ jitter บนจอ ~12 px ที่ 1920 — ยังไม่ได้วัด)
- `keepWhileAboveHips = 1.0` เปิดใช้

ตรวจ: 165 test ผ่าน (fidget / ยืนนิ่ง ยังไม่มี cursor — เกณฑ์เริ่มไม่เปลี่ยน)
replay playground กับกรอบใหม่ได้ 9 ครั้ง (ปุ่ม 5 = 2) — **ใช้ตัดสินไม่ได้** เพราะท่าที่อัดเล่นกับกรอบเก่า (ชี้) ไม่ใช่แบบเลื่อนมือข้างตัว → ต้องเล่นจริงรอบใหม่

replay รอบ 7 ได้ **23 ครั้ง ตรงกับตอนเล่นจริงทุกปุ่ม** → ใช้วัดได้

### รอบที่ 8 — สมมติฐาน "หลุดขอบนิดเดียว" (`stayPadding`)
บันทึกบอกว่าตอนหลุดอยู่นอกขอบแค่ 0.002–0.029 → ลองยอมให้ล้นขอบ 0.02…0.06
**ผล: 23 ทุกค่า — ไม่ช่วย** → ไล่เส้นทาง cursor หลังหลุด: ตัวเลขข้างบนเป็นแค่ *เฟรมแรก* ที่หลุด; หลังจากนั้น cursor เลื่อนต่อไป 0.08–0.2 แบบลื่น ๆ เข้าปุ่มข้าง ๆ, 4/6 ครั้งวกกลับมา (เช่น 5 → 4 → 5 ใน 1.6 s) — ดูเหมือนเลยเป้าแล้วแก้ (cursor ไวขึ้น 2.4×) แต่**แยกจากการย้ายปุ่มโดยตั้งใจไม่ได้จากข้อมูล**
→ **สมมติฐานผิด**

### รอบที่ 9 — เก็บความคืบหน้าไว้แล้วค่อย ๆ ลด (`decayMs`)
ระหว่างทาง: implementation แรกไม่นับช่วงหลุด ≤ 150 ms เป็นเวลาค้าง (ต่างจากเดิมโดยไม่ตั้งใจ) — unit test จับได้ แก้ก่อนวัด

| decay | กดติด | หลุดกลางทาง | เวลาจนติด avg / max | ปุ่มอื่นติดตามใน 1 s |
|---|---|---|---|---|
| 0 | 23 | 6 | 1.18 / 1.18 s | 0 |
| 1200 | 23 | 5 | 1.23 / 2.33 s | 0 |
| 2000 | 23 | 3 | 1.26 / 2.10 s | 0 |
ตัวชี้วัดแรก (จำนวนกดติด) ไม่ไว — เพราะสุดท้ายเจ้าของงานกดติดเกือบทุกครั้งที่หลุดอยู่แล้ว → เปลี่ยนมาวัดการหลุดและเวลาจนติด
**ผล: ลดการหลุดได้เล็กน้อย แต่ไม่เพิ่มการกดติด และบางครั้งช้าลง** → **ไม่ใช้** (ทั้ง stayPadding และ decay ถูกเอาโค้ดออก ไม่เพิ่มความซับซ้อนที่ไม่มีหลักฐาน)

## ข้อสรุป (ถึงรอบ 9)
- **พื้นที่มือข้างตัว + ชี้ต่อเมื่อยกค้าง (1.0)**: ปุ่มหน้าตัวกดได้ (0 → 3), cursor ไม่หายระหว่างกด, เจ้าของงานรู้สึกดีขึ้น — **ใช้**
- ปัญหาที่เหลือ: **หลุดเป้า 6/29** จาก cursor ที่ไวขึ้น / มือไหล — ทางแก้ฝั่ง dwell ไม่ได้ผล → ถ้าจะแก้ต่อ ต้องแก้ที่การเคลื่อนของ cursor (เช่นกรอบใหญ่ขึ้น = ไวน้อยลง แลกการเอื้อม, หรือความไวแปรตามความเร็วมือ) ซึ่งต้อง playtest ใหม่
- replay test ถาวร: ทุกปุ่มต้องกดติดได้ไม่น้อยกว่าตอนเล่นจริง และปุ่ม 5 ≥ 3 (ตรวจแล้วว่า test ล้มถ้าใช้กรอบเก่า)

## ข้อจำกัด
- เล่นคนเดียว 2 รอบ บนจอโน้ตบุ๊ก — ทีวีจอใหญ่และผู้เล่นคนอื่น (เด็ก) ยังไม่ได้วัด
- จากข้อมูลบอกเจตนาไม่ได้ (ตั้งใจย้ายปุ่ม vs มือไหล)
