# 020 — EPISODE IV จับโกงข้ามกาแล็กซี (Anomaly Detection)

- **วันที่:** 2026-10-29 · **สถานะ:** สรุปแล้ว (รอลองสด)
- **เกี่ยวข้อง:** `app/src/scenes/fraud/{model,scene}.ts` · `fraud.css` · `content/story.th.yaml` (`fraud`) · `tests/unit/fraud-model.test.ts` · `tests/e2e/fraud.spec.ts`

## คำถาม

เจ้าของงานต้องการให้การเล่าเรื่อง "จัดมาก ๆ" และน้องได้เล่นเยอะกว่าบทก่อน ๆ บทนี้จะสอน Anomaly Detection ยังไง ให้น้องไม่ได้แค่ตบรายการแล้วนั่งดูเฉลย

## ออกแบบ

**ช่วงเล่น 1: ยิงโกง (20 วิ)**

- รายการบินออกจากประตูไฮเปอร์สเปซ
- ดาวแหลมสีแดง = โกง · วงกลมฟ้ามีเครื่องหมาย ✓ = ลูกค้าดี (ต่างกันทั้งรูปทรงและสี ไม่พึ่งสีอย่างเดียว)
- ปัดมือเร็ว ๆ = ลำเลเซอร์ (ท่าตบ research 019) ยิงโดนโกงแตกเป็นประกาย นับคอมโบ ยิงโดนคนดีจะมีโล่ฟ้าเด้ง
- ยิ่งเล่นยิ่งเร็ว 5 วินาทีสุดท้ายถี่จนคนทำไม่ทัน ใช้ปูเรื่องว่าทำไมต้องใช้ AI

**เฉลย**

1. พายุ 1,000,000 รายการพุ่งเข้าแผนที่ (ระยะจากบ้าน × ยอดเงิน, log ทั้งสองแกน) ตัวนับวิ่ง และ**เวลาที่ AI ใช้เป็นเวลาจริงที่วัดได้**
2. AI วัดว่าแต่ละจุดห่างจาก "ปกติ" กี่ σ (Mahalanobis จากค่าเฉลี่ยและความแปรปรวนของทุกรายการ โดย AI ไม่รู้ว่ารายการไหนโกง) แล้ววงขยายออกจากกลางฝูง
   - ในวง = ชมพู · นอกวง = ฟ้า (ลูกค้าดีโดนบล็อก) · โกง = แดง (สว่างเมื่อจับได้ จางเมื่อหลุด)
3. กากบาทและวงกลมบนแผนที่คือรายการที่น้องยิงจริงในช่วงเล่น ใช้โยงช่วงเล่นกับเฉลยเข้าด้วยกัน

**ช่วงเล่น 2: น้องเลือกขนาดวงเอง (12 วิ)**

- ยกมือ = ขยายวง · ลดมือ = หดวง ใช้ท่า raise เดียวกับ EPISODE II
- ตัวเลขเปลี่ยนตามมือทันที: % ที่จับโกงได้, จำนวนลูกค้าดีที่โดนบล็อก, ความเสียหายรวม พร้อมกราฟรูปตัว U ที่มีจุดของน้องวิ่งไปตาม
- หมดเวลาแล้วเฉลยวงที่เสียหายน้อยสุดเป็นวงสีเขียว lesson ปิดว่า "Data Scientist คือคนเลือกว่าวงควรใหญ่แค่ไหน"

## การทดลอง

### รอบที่ 1 — ข้อมูลและต้นทุน

สร้างธุรกรรมแบบสุ่ม (seeded) 1,000,000 รายการ โกง 1% แบ่งเป็น 3 แบบ: ต่างประเทศยอดใหญ่ / ใกล้บ้านยอดใหญ่ / ไกลแต่ยอดจิ๋ว ("ลองบัตร") สองแบบหลังจงใจให้ทับหางของรายการปกติ ไม่มีวงไหนจับได้หมดโดยไม่บล็อกใคร

ต้นทุนที่ตั้งไว้: โกงหลุด ฿6,000 / รายการ · บล็อกผิด ฿150 / คน

| วง (σ)            | จับโกงได้ | บล็อกคนดี  | ความเสียหาย |
| ----------------- | --------- | ---------- | ----------- |
| 1.2               | 99.6%     | 436,219    | ฿65.7M      |
| 2.0               | 95.9%     | 101,799    | ฿17.8M      |
| **2.59 (ต่ำสุด)** | **88.4%** | **22,151** | **฿10.4M**  |
| 3.2               | 78.8%     | 2,167      | ฿13.2M      |
| 4.0               | 69.2%     | 65         | ฿18.8M      |
| 4.8               | 58.5%     | 3          | ฿25.2M      |

ได้กราฟรูปตัว U ชัดเจน ตอนแรกตั้งช่วงวงไว้ 1.5–6σ จุดต่ำสุดตกที่ระดับมือ 0.24 ซึ่งเกือบเป็นมือลง → เปลี่ยนช่วงเป็น **1.2–5σ** จุดต่ำสุดจึงอยู่ที่ระดับมือ 0.37 (ยกมือราวเอว–อก)

### รอบที่ 3 — ยิงไม่ค่อยโดน (E2E ร่างกายสังเคราะห์)

- ปัดสุ่มไม่เล็ง: ยิงได้ 2 → ยังบอกอะไรไม่ได้ จึงให้ test เล็งยานแดงจริงผ่าน `body[data-fraud-target]`
- เล็งแล้วยังได้แค่ 3–5 ลำ: hook ส่งลำที่ใกล้หลุดที่สุด (ชิดขอบซ้าย) มาให้ การเล็งจึงถูกบีบไปที่ขอบจอ → เปลี่ยนเป็นลำที่เพิ่งออกจากประตู
- **สาเหตุจริง:** log ของ slap event พบว่ามาแค่ 1–2 ครั้งต่อการปัดหนึ่งครั้ง เพราะท่าตบจะติดหลังการปัดเร็วไปแล้ว 1–2 เฟรม ถ้า hit-test เฉพาะจุดของ event ทางเลเซอร์จะเป็นจุดห่าง ๆ และช่วงแรกของการปัดหายไป
  - แก้: ฉากเก็บเส้นทาง cursor ทุกเฟรม พอ slap ติด ให้นับทั้งเส้นทางย้อนหลัง 100 ms ที่ทำให้ถึงเกณฑ์ แล้วต่อเฟรมต่อเฟรมจนช้าลง
  - ผล: 3 → **9–16** ลำ ผู้เล่นจริงก็จะเจอแบบเดียวกัน (ฟันผ่านแล้วไม่โดน) ถ้าไม่ได้แก้
- รัศมีโดน 0.055 → 0.075 ความสูงจอ

## ทางเลือกที่ไม่เลือก

- **Isolation Forest:** แม่นกับรูปร่างข้อมูลแปลก ๆ แต่อธิบายให้เด็กเข้าใจยาก และวาดเป็นวงไม่ได้ ส่วน Mahalanobis ได้ "วง" ที่เห็นและเลือกเองได้
- **ยืนยันขนาดวงด้วยปุ่มชี้ค้าง:** มือกำลังยกปรับวงอยู่ ปุ่มอาจถูกเลือกเองโดยไม่ตั้งใจ จึงใช้การจับเวลา 12 วิแทน
- **วาด 1M จุดทีละจุดด้วย WebGL:** ทำได้ แต่ภาพความหนาแน่นสื่อ "กลุ่มปกติ" ได้ชัดกว่า และถูกกว่ามาก
