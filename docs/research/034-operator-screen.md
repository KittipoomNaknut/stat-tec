- ต่อ 2 จอ: จอหลักให้น้องเล่น อีกจอให้สตาฟเห็นการจับท่าแบบตอนกด F1 พร้อม log
- ข้อกำหนด: "อย่าให้กระทบประสิทธิภาพเกม"

## ออกแบบให้เบา

- **หน้าแยก ไม่ใช่เปิดเกมซ้ำ:** ใช้ canvas 2 มิติอย่างเดียว ไม่มี three.js ไม่มี animation และวาดใหม่เฉพาะตอนมีข้อมูลใหม่
- **ภาพกล้อง:** ใช้ JPEG ตัวอย่างตัวเดิมที่ server ทำให้ช่องดูตัวเองมุมขวาบนอยู่แล้ว ไม่ต้องบีบอัดภาพเพิ่ม
- **ไม่จับท่าเพิ่ม:** estimator เก็บสิ่งที่ตัวกรองเห็นไว้ (`record_scene`) **เฉพาะตอนที่มีจอสตาฟเชื่อมต่ออยู่**
  - ใช้ 0.09 ms ต่อภาพ ส่งให้จอสตาฟ 15 ครั้งต่อวินาที
  - ไม่มีจอสตาฟ = ไม่มีงานเพิ่ม (มีเทสต์ยืนยัน)
- **จอสตาฟเชื่อมต่อที่ path `/operator`:** ระบบไม่นับว่าเป็นหน้าเกม
  - กฎ `app-missing` ยังเปิดเมื่อหน้าเกมปิด
  - ไม่เขียน app-connected ลง log
  - ไม่ได้รับ detections ของเกม
- **log:** ใช้ `describe()` และ `Day` ตัวเดียวกับ `stat-tec-log` จึงได้บรรทัดภาษาไทยและสรุปของวันชุดเดียวกัน
  - เชื่อมต่อแล้วจะได้ log ย้อนหลัง 40 บรรทัดทันที

## บนจอ

- **ภาพกล้อง:** กลับซ้าย-ขวาเหมือนในเกม
  - **เส้นโซน:** สีชมพู
  - **กรอบส้มประ:** ไม่ถูกจับท่า แปะเหตุผล เช่น "นอกโซน", "ตัวเล็ก / อยู่ไกล"
  - **โครงกระดูกเขียว "✓ ผ่าน":** ส่งให้เกม
  - **โครงกระดูกเทา "✕ ...":** ถูก body check ตัด แปะเหตุผล เช่น "หัวไม่อยู่ระหว่างไหล่", "ชิดขอบภาพ", "เห็นหัว-ไหล่ไม่ชัด", "ลำตัวผิดสัดส่วน"
- **ช่องสถานะ:** กล้อง fps · จับท่า ms · เกม fps (ขึ้น "ไม่ได้เปิด" ถ้าหน้าเกมไม่เชื่อมต่อ) · GPU/CPU °C · คนในภาพ
  - สีเขียว เหลือง แดง ใช้เกณฑ์เดียวกับ `stat-tec-log`
- **กล่องปัญหาสีแดง:** บอกวิธีแก้ สรุปของวัน และ log สด

## ผล

- **pytest:** 30 passed
  - เพิ่มเทสต์ว่าจอสตาฟได้ scene, สถานะ และภาพตัวอย่าง
  - ไม่ได้ detections
  - ไม่นับเป็นเกม
  - ได้บรรทัด log เมื่อหน้าเกมต่อเข้ามา
  - ปิดจอสตาฟแล้ว `record_scene` กลับเป็น false
- **ภาพหน้าจอ:** ใช้ server ทดสอบที่ส่งผลจับท่าจากภาพนักฟุตบอล (ไม่ใช่กล้อง) แสดงครบทุกส่วน
  - คนนอกโซนเป็นกรอบส้ม ส่วน 3 คนที่ผ่านเป็นสีเขียว
  - ปัญหา `slow-pose` และ `app-missing` ขึ้นในกล่องแดงพร้อมวิธีแก้
- **CPU ของหน้าจอสตาฟ:** ประมาณ 32% ของ 1 core จาก 20 thread (ประมาณ 1.6% ของทั้งเครื่อง)
  - วัดใน Chromium แบบไม่แสดงหน้าต่าง ซึ่งวาดด้วย CPU ถือเป็นกรณีแย่ที่สุด
- **`demo.sh start --operator`:** อ่านจอจาก `xrandr --listmonitors`
  - ค่าเริ่มต้นวางจอสตาฟบนจอที่ไม่ใช่จอหลัก (HDMI) เพราะเกมเปิดบนจอหลัก
  - เปลี่ยนได้ด้วย `STAT_TEC_OPERATOR_SCREEN=eDP-1`
  - หน้าต่างจอสตาฟใช้ X11 (XWayland) เพื่อให้วางบนจอที่กำหนดได้ แต่เกมยังเปิดแบบเดิมทุกอย่าง

## ระหว่างทำ (บทเรียน)

- **เทสต์ครั้งแรกชนกับเกมที่เจ้าของงานเล่นอยู่:** port 8765 มีตัวจับท่าจริงทำงานอยู่ จึงได้ภาพหน้าจอที่อาจมีภาพกล้องจริง
  - ลบภาพทิ้งทันทีโดยไม่เปิดดู
  - server ทดสอบใช้ GPU อยู่ประมาณ 20 วิ อาจทำให้เกมช้าลงช่วงสั้น ๆ
  - ครั้งต่อไปใช้ port 8799 และให้ผลจับท่าที่คำนวณไว้ก่อนเล่นซ้ำ ไม่ใช้ GPU
- **กฎ:** ต้องเช็ก port 8765, 8080 และ `fuser /dev/video*` ก่อนทดสอบทุกครั้ง
