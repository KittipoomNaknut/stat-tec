## สิ่งที่พบ

1. **กล้องลด fps เองเมื่อแสงน้อย:** log ของรอบที่ลองสดบอกว่ากล้องได้แค่ **10–16 fps** ตลอดรอบ ระบบเปิดปัญหา `low-fps` ทันที
   - ค่าควบคุม `exposure_auto_priority` ของ HD Webcam ถูกตั้งเป็น **1** (ค่าโรงงานคือ 0) ค่านี้ยอมให้กล้องลด fps เพื่อเปิดรับแสงนานขึ้น
   - cursor ที่ 12 fps จะหน่วงและกระตุกเสมอ ตัวกรองแก้ไม่ได้
2. **ข้อมือหลุดกรอบ:** YOLOX-m หาคนแค่ทุก 7 ภาพ (19 ms ต่อครั้ง) ภาพระหว่างนั้นใช้กรอบจากข้อต่อของภาพก่อน ขยายแค่ 25%
   - แขนที่ขยับเร็วจะออกนอกกรอบ ข้อมือที่ได้จึงผิดตำแหน่ง แขนดูงอหรือสั้น cursor เลยเป็นสีเทาหรือตามไม่ทัน
   - ตรงกับแนวทางของ LightTrack / MMPose ที่ขยายกรอบ หรือหาคนใหม่เมื่อความมั่นใจของข้อมือตก
3. **กฎ "ชี้" เข้มเกินไป:** เมื่อข้อมืออยู่สูงระดับไหล่ขึ้นไปแต่ cursor ยังเป็นสีเทา (4–7% ของเวลาใน session ที่อัดไว้) ส่วนใหญ่เพราะกฎตัดสินว่าแขน "งอ" (ความตรง < 0.8) หรือ "สั้น" (ระยะยื่น < 0.9)
4. **ผ่อนกฎหรือเร่งตัวกรองตรง ๆ ใช้ไม่ได้:**
   - ผ่อนกฎเป็น 0.7/0.75 ทำให้เทสต์ idle-fidget ล้ม: cursor ขาวและกดปุ่มเต็มจอได้ทั้งที่แค่ขยับตัว
   - เร่งตัวกรอง (1.0/20) และลด precision (0.6/25) ช่วยให้หน่วงลด 17% แต่**สั่นเพิ่ม 30%** และไม่ผ่านเทสต์ความนิ่ง
   - สรุป: ต้องแก้ที่ข้อมูลข้อต่อที่ส่งเข้ามา ไม่ใช่ที่ตัวกรอง
5. **ชี้ตรงเข้าหากล้องใช้ไม่ได้ด้วยกล้อง 2 มิติ:** พื้นที่ที่ระบบแปลงเป็นจออยู่ข้างไหล่ (research 010) ถ้าชี้ตรงไปที่จอ ข้อมือจะทับไหล่ cursor จะไปอยู่มุมซ้ายล่าง
   - Kinect แก้ได้เพราะมีกล้องวัดความลึก เรามีแค่ภาพ 2 มิติ
   - ผู้เล่นต้องขยับมือในระนาบข้างตัว และต้องมีอะไรบอกให้รู้

## ข้อมูลจากภายนอก

- **Kinect for Windows (KinectInteraction):**
  - มือเป็น "interactive" เมื่อยกเข้ามาใน Physical Interaction Zone และเลิกโดยลดมือลงข้างตัว ไม่มีเงื่อนไขว่าแขนต้องตรง
  - มี User Viewer (ภาพผู้เล่นมุมจอ) ช่วยให้ผู้เล่นรู้ว่าระบบเห็นตัวเอง เราทำแล้วใน #54/#58
  - ที่มา: [KinectInteraction Concepts](<https://learn.microsoft.com/en-us/previous-versions/windows/kinect-1.8/dn188673(v=ieb.10)>)
- **UVC:**
  - `exposure_auto_priority=1` ยอมให้ลด fps เพื่อแลกความไวแสง ถ้าต้องการ fps คงที่ให้ปิด แล้วชดเชยด้วย gain
  - ที่มา: [gist](https://gist.github.com/lasombra/503304919e2b5150557cc0bf54691810), [Arducam forum](https://forum.arducam.com/t/v4l-ctl-settings-for-low-light-imx291/1543)
- **Top-down tracking (LightTrack):**
  - ใช้กรอบจากข้อต่อของภาพก่อน ขยาย 20% และหาคนใหม่เมื่อหลุด
  - ที่มา: [US11288835](https://patents.google.com/patent/US11288835), [MMPose pose tracker node](https://mmpose-ly015.readthedocs.io/en/latest/_modules/mmpose/apis/webcam/nodes/model_nodes/pose_tracker_node.html)
- **เด็กกับ gesture กลางอากาศ:**
  - เด็กชอบท่าทั้งตัวและท่าที่ชัดเจน เงาคนหรือ avatar ช่วยให้รู้ว่าทำอะไรได้
  - ที่มา: [Remizova, Tampere Univ.](https://trepo.tuni.fi/handle/10024/233630)

- **เทสต์ที่เปลี่ยน:**
  - `cursor-precision`: เกณฑ์ steady 0.80 → **0.82** เพราะกฎใหม่ทำให้ cursor ขาวเร็วขึ้นเล็กน้อย ช่วง 600 ms ก่อนกดจึงรวมจังหวะที่มือยังเคลื่อนเข้าหาปุ่มทั้งสองขั้น (10.5/13.4 → 12.3/15.1) precision ยังลดได้ ≥ 18%
  - unit test "ตามมือที่สูงกว่า": มือที่ตั้งใจให้ "งอ" ต้องงอจริง (ใส่ข้อศอก) และมือขวาต้องต่ำกว่าระดับเริ่มชี้
- **เทสต์ใหม่:**
  - **cursor:** เริ่มชี้ในพื้นที่ได้ทั้งที่แขนไม่ตรงสุด และไม่ติดเมื่อเกาหัว
  - **ตัวจับท่า:** หาคนทุกภาพ และไม่หลุดเมื่อพลาดภาพเดียว · ตั้งค่า fps กล้องเมื่อไม่มีกล้องแล้วไม่พัง
  - **E2E:** ป้ายบอกวิธีชี้

## ยังต้องทำ

- **ลองกับกล้องจริง (ต้องมีเจ้าของงาน):** เปิดไฟห้องแล้วดูว่า fps ขึ้นเป็น ~30 จริงไหม (บรรทัด `camera … frame rate held` ใน `perception.log`)
- **เทียบรอบเก่ากับรอบใหม่:** ใช้ playground + F9 ดูว่าสีเทาน้อยลงและตามมือทันขึ้นจริงไหม · ถ้าไฟล์ F9 ไม่ลงมาอีก ต้องหาสาเหตุ (รอบที่ลองวันนี้ไม่ได้ไฟล์)
- **ถ้าภาพมืดเกินจนจับท่าพลาด:** เพิ่ม gain หรือ brightness
